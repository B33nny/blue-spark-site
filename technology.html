Local memory. Deliberate cloud assistance.

Your working context should have a clear home. Blue Spark’s local-first design separates the memory kept on your computer from the task context sent to a cloud model when external reasoning is used.

What stays with your Blue Spark.

Persistent memory is maintained locally, and retrieval selects relevant information from that local store. The model provider is not given unrestricted access to browse the complete memory database.

What a cloud model receives.

For a cloud-assisted task, Blue Spark sends the instructions and selected context needed for that work. This may include relevant information from your documents or memory. The receiving provider processes the content sent to it.

Permission once—not the same question every step.

Standing permission allows authorized cloud assistance to continue without repeated routine approvals. It is permission for the described cloud use, not an unlimited instruction to perform unrelated actions.

The model is a resource. The worker is Blue Spark.

Models contribute reasoning. Blue Spark’s purpose is to bring that reasoning together with your working context and the tools used to carry out the job. The product is more than a model name.

Clear boundaries matter.

Local storage and cloud processing are different things. Read the privacy notice for the actual service providers, data categories, retention arrangements, and available controls that apply to your configuration.
